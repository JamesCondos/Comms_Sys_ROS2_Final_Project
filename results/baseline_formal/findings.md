# Experiment 1: findings

The baseline remained below sustained overload through 32 robot-equivalents
(1,024 messages/s). At 64 robot-equivalents (2,048 messages/s), the bounded FIFO
remained almost full, throughput could not keep up, and queue overflow discarded
38.92% of generated messages.

These are actual measurements of ROS2 Humble -> FIFO gateway -> persistent
HTTP/1.1 -> REST server, running on clean loopback in Ubuntu 22.04 WSL2.
Robot-equivalents are synthetic identities generated by one ROS2 source process.
The gateway and server run in separate processes on the same machine.

## Method

- Seven load levels: 1, 2, 4, 8, 16, 32 and 64 robot-equivalents.
- Three repetitions each, in seeded shuffled order: 21 formal runs.
- Five-second warm-up, 60-second measurement, bounded drain afterward.
- Four periodic traffic classes with the supplied rates and payload sizes.
- A 1,000-message FIFO, drop-tail admission, one sender and one outstanding request.
- One persistent HTTP/1.1 connection per run; no application retries or injected faults.

Short smoke and pilot runs are stored separately and excluded from these aggregates.
The pilot justified extending the original 1/2/4/8 sweep to higher loads.

## Observations

| Metric | 32 robot-equivalents | 64 robot-equivalents |
|---|---:|---:|
| Offered load | 1,024 messages/s | 2,048 messages/s |
| Mean completed throughput | 1,024 messages/s | 1,250.8 messages/s |
| Mean of run p95 latencies | 6.45 ms | 1,163.36 ms |
| Command p95, mean across runs | 6.70 ms | 1,158.69 ms |
| Time-averaged waiting queue, mean across runs | 2.12 messages | 997.97 messages |
| FIFO overflow fraction | 0% | 38.92% |
| Payload goodput, mean across runs | 27.06 Mbit/s | 33.80 Mbit/s |

At 64 robot-equivalents, mean gateway queue waiting time was approximately
798.6 ms, compared with 0.79 ms for the HTTP exchange and 0.45 ms from publication
to the gateway. The large delay is predominantly waiting for the single sender.
The critical command class receives no latency protection from FIFO.

The 64-robot throughput varied from 1,181.6 to 1,344.7 messages/s across repeats.
Its p95 latency varied from 1,105.0 to 1,210.4 ms. All lower-load formal runs
completed the offered traffic without overflow.

Across the complete formal measurement cohort:

- 731,520 messages were generated and observed by the gateway.
- 588,044 completed successfully, including the drain period.
- 143,476 were dropped at FIFO admission.
- Zero HTTP errors, missing ROS messages or messages pending after drain were found.
- Every run used exactly one accepted HTTP connection and HTTP/1.1 throughout.

Overflow occurred at gateway admission. Admitted messages completed successfully
over HTTP/TCP. This establishes queue overload behaviour without invoking an
application-layer fault injector or ARQ scheme.

## What this establishes

The measured overload transition lies between the tested 1,024 and 2,048 messages/s
loads. This sweep does not locate an exact threshold. For subsequent experiments,
32 robot-equivalents is a useful high-load reference without sustained overload,
and 64 is a reproducible FIFO stress condition on this implementation and host.

The result characterises the combined single-sender software path on a shared
WSL2 host. It does not isolate physical network capacity or server capacity.
Recalibrate after changing concurrency, implementation, protocol or hardware.
No M/M/1 assumptions or statistical significance claims are made.
